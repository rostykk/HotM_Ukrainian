# Українська локалізація Heart of the Machine

Неофіційний фанатський переклад [Heart of the Machine](https://store.steampowered.com/app/2001070/) (Arcen Games)
українською разом із доповненням Kinship, а також інструменти, якими його зроблено й підтримують після
кожного оновлення гри.

| | |
|---|---|
| Версія перекладу | 1.3 |
| Версія гри | 2_004_Update92 (збірка Steam 26259162) |
| Перекладено | 20 824 рядки з 20 824 — інтерфейс, події, розмови, проєкти, довідник, досягнення, DLC Kinship |
| Як зроблено | машинний переклад (Claude, Gemini) з глосарієм ~1200 термінів і кількома проходами редактури: терміни, природність мови, синтаксичні кальки |

**Гравцям.** Готовий архів з інсталятором для Windows, Linux і Steam Deck та інструкція — у посібнику Steam
«Українізатор Heart of the Machine». Помітили помилку — напишіть у коментарях під посібником англійський
текст або знімок екрана і свій варіант.

**Що в репозиторії.** `hotm_uk.py` — увесь конвеєр, `uk_translation.xlsx` — робочий файл перекладу,
`text\` — його текстова копія для git diff, `STYLE_uk.md` — правила стилю, `glossary.xlsx` — глосарій,
`dist_template\` — шаблони архіву й посібника, `voice_mod\` — прототип озвучки (див. нижче).
Історія версій — `dist_template\changelog.txt`, теги релізів `vX.Y`.

## Звідки береться англійський текст

Англійського xlsx у грі немає: англійська мова — це сам XML (`is_original_english="true"`).
`hotm_uk.py` збирає його так само, як офіційний експортер Arcen:

- `GameData\Configuration\*\*.xml` і `Expansions\<DLC>\*\*.xml`. XML з DLC — це повноцінний контент;
  `ExpansionInstallation.txt` лише позначає, що DLC встановлено;
- поле перекладається, якщо в `.metadata` таблиці воно має `is_localized="true"` (`display_name`/`description` за замовчуванням);
- ключ: `Таблиця|id|поле`, для вкладених вузлів `Таблиця|id|вузол|id_вузла|поле` (і глибше).
  Для `0_Language` ключ — просто `id`;
- вузли з `skip_all_localization_on_node="true"` пропускаються;
- старі «споглядання» (`tl="OC"`) мають ключі `ContemplationType|<id без Cont_>|поле`;
- ключі з лівого боку `LocalizationImports\ALL-LOCA-LINKS.txt` беруть переклад з правого, тому
  перекладати їх не треба. Гра сама застосовує ці посилання.
  Якщо ціль посилання — `NPCEvent|Cont_X|поле` без власного рядка, `build` дописує її з перекладом `ContemplationType|X|поле`.

Перевірено на версії 2_001_Update89: з 20 699 ключів офіційних xlsx 20 611 збігаються.
Решта 88 — застарілі ключі вилученого контенту.

## Середовище

Залежності встановлюються у віртуальне середовище `.venv` в корені проєкту (його немає в git):

```
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Скрізь нижче `python` означає `.venv\Scripts\python.exe`. Щоб писати просто `python`, активуйте
середовище: `.venv\Scripts\Activate.ps1`.

## Робочий процес

```
python hotm_uk.py sync      # витягнути англійський текст і оновити uk_translation.xlsx
python hotm_uk.py build     # зібрати GameData\LocalizationImports\Ukrainian.xlsx
python hotm_uk.py status    # скільки перекладено
python hotm_uk.py dump      # оновити текстову копію text\*.json (після ручних правок у Excel)
python hotm_uk.py pseudo    # тестовий файл: "ЇҐ·" + англійський текст (перевірка шрифтів)
```

Тека гри задається через `--game "D:\SteamLibrary\steamapps\common\HeartOfTheMachine"` або змінну
середовища `HOTM_DIR`.

1. `sync` створює або оновлює `uk_translation.xlsx`.
2. Перекладайте в колонці **Українська**. Колонка `German (довідка)` містить офіційний німецький переклад, з якого видно роди й відмінки.
3. `build` записує `Ukrainian.xlsx` у тому самому форматі, що й офіційні файли. Якщо оновлення гри
   стерло запис мови з `LocalizationTypes.xml`, `build` додає його знову з `localization_type_uk.xml`.
   Резервні копії лежать у `backup\`.

## Після оновлення гри

Спершу `sync --dry-run`: він нічого не записує, лише показує, скільки рядків нових, змінених і видалених.
Якщо «видалених» раптом сотні, найімовірніше, якийсь XML гри не розібрався (скрипт пише `! не вдалося
розібрати …`). Arcen інколи склеює атрибути без пробілу (`id="X"text="…"`): такі файли `hotm_uk.py` уже
виправляє сам, але інші помилки формату варто перевірити до справжнього `sync`.

Далі запустіть `sync`. Він:
- додає нові рядки (статус `new`);
- позначає рядки зі зміненим англійським текстом статусом `changed`. Старий англійський текст, з якого
  зроблено переклад, з'являється в колонці «Попередній English», а сам переклад лишається;
- переносить вилучені рядки з перекладом на аркуш «Видалено». Якщо ключ повернеться, переклад відновиться;
- підставляє готовий переклад, якщо такий самий англійський рядок уже перекладено (статус `auto`);
- записує звіт `changes\<дата>_<версія>.xlsx` (аркуші «Нові», «Змінені», «Видалені») і знімок
  `snapshots\en_<версія>_b<збірка Steam>.json`.

Далі відфільтруйте колонку «Статус» і запустіть `build`.

**Чому в назві знімка є збірка Steam.** Arcen буває змінює тексти, не змінюючи id версії в
`GameVersions.xml`. Наприклад, 13.10.2026 збірка 25896203 виправила `MachineProject|DLC1_MIN_TrashDeer|description`,
а версія лишилася `2_001_Update89`. Номер збірки (`buildid`) береться з `steamapps\appmanifest_2001070.acf`
і змінюється з кожним оновленням, тож знімки різних збірок не перезаписують один одного.
`snapshots\en_2_001_Update89.json` — знімок, з якого зроблено реліз 1.0 (збірка до 25896203).

## Git і текстова копія

Проєкт ведеться в git. `uk_translation.xlsx` і `glossary.xlsx` — двійкові, git не показує, що в них
змінилося. Тому скрипт поруч пише їхню текстову копію:

- `text\translation.json` — ключ → English, переклад, статус, перекладач, попередній English, примітка, файл;
- `text\removed.json` — аркуш «Видалено»;
- `text\glossary.json` — глосарій;
- `text\info.json` — аркуш «Інфо» (версія, збірка, дата синхронізації).

Копія оновлюється сама, коли скрипт записує робочий файл чи глосарій (`sync`, `import`, `replace`,
`glossary`) і під час `build`. Після ручних правок у Excel запустіть `build` або `dump` перед комітом.
Похідні колонки («Місце», «German (довідка)») у копію не потрапляють: `sync` їх перераховує.

Типовий цикл після оновлення гри:

```
python hotm_uk.py sync
git add -A
git commit -m "sync: <версія> b<збірка>"
# ...переклад нових/змінених рядків...
python hotm_uk.py build
git add -A
git commit -m "переклад змін <версія>"
```

`git diff text\translation.json` показує зміни перекладу рядок за рядком. Як змінився англійський
текст між двома збірками, видно з `git diff --no-index snapshots\en_<стара>.json snapshots\en_<нова>.json`.

## Статуси

| статус | значення |
|---|---|
| `new` | не перекладено. Коли заповните переклад, `sync` сам змінить статус на `ok` |
| `changed` | англійський текст змінився. Перевірте переклад і поставте `ok` |
| `auto` | переклад підставлено з ідентичного рядка. Перевірте і поставте `ok` |
| `mt` | машинний переклад (Claude/Gemini), потребує редактури. Хто перекладав, видно в колонці «Перекладач» |
| `ok` | готово |

## Переклад через ШІ (батчі)

```
python hotm_uk.py glossary            # кандидати в терміни -> glossary.xlsx
python hotm_uk.py export --glossary   # батчі термінів (batches\g01)
python hotm_uk.py export              # батчі рядків new/changed (batches\r01), з потрібними термінами глосарію
python hotm_uk.py claim claude 4      # Claude бере 4 батчі з початку
python hotm_uk.py claim gemini 4 --from-end   # Gemini бере з кінця, сходимось посередині
python hotm_uk.py batches             # стан
python hotm_uk.py import              # забрати відповіді з batches\*\out\*.json
```

- Батч — це JSON з короткими id. Кожен елемент містить ключ (`k`, щоб було видно контекст), англійський
  текст, німецький довідковий переклад і примітку розробників. До батчу додаються лише ті терміни
  глосарію, що в ньому трапляються. Записи гри не розрізаються між батчами, тож діалог лишається в одному.
- Відповідь — JSON `{"1": "переклад", ...}`, а файл відповіді має той самий номер, що й батч. Деталі для Gemini — у `PROMPT_gemini.md`.
- Стиль перекладу (звертання на «ви», регістр, лапки, теги) описано в `STYLE_uk.md`. Він спільний для всіх перекладачів.

## Глосарій і редактура термінів

`glossary.xlsx`: English → Українська, «Варіанти» (допустимі альтернативи через `;`), «Примітка» (рід,
відмінювання), «Статус» (`candidate` — не перекладено, `proposed` — запропонував ШІ, `ok` — затверджено, `skip` — не термін).
Порядок рядків — від найчастіших термінів.

```
python hotm_uk.py terms            # terms_report.xlsx: рядки, де переклад не відповідає глосарію
python hotm_uk.py export --review  # батчі для ШІ-редактора: виправити лише термінологію
python hotm_uk.py import
```

`terms` враховує відмінки: порівнює основи слів, тож «ментальної енергії» зараховується як «ментальна енергія».
Якщо ви змінили термін у глосарії, `terms` покаже всі рядки зі старим варіантом.

`build` включає всі непорожні переклади. Ключ `--skip-changed` пропускає застарілі (`changed`).

## Редактура після перекладу

```
python hotm_uk.py terms                 # звіт terms_report.xlsx: розбіжності з глосарієм
python hotm_uk.py export --review       # батчі для ШІ-редактора термінів
python hotm_uk.py export --shorten      # кнопки/мітки й назви, задовгі для свого місця в інтерфейсі
python hotm_uk.py export --fix-issues   # технічні проблеми: переноси, теги, пробіли, заборонені слова
python hotm_uk.py export --glossary-review  # редактор проходить увесь глосарій
python hotm_uk.py replace "старе" "нове" [--regex] [--dry-run]   # масова заміна в перекладі
python hotm_uk.py check batches\r01\001.json                      # перевірити відповідь ШІ до імпорту
python hotm_uk.py release [gemini]      # повернути у вільні взяті батчі без відповіді (обірвався ліміт)
```

**Колонка «Місце»** у `uk_translation.xlsx` показує, де рядок з'являється в грі. Її визначає аналіз
C#-коду інтерфейсу гри разом із типом поля:
- `кнопка` — кнопки, вкладки, мітки, `short_name`, назви клавіш. Довжину треба тримати близькою до англійської;
- `назва` — заголовки підказок і назви в списках;
- `текст` — описи, підказки, діалоги. Тут довжина не важлива.

Звіт `build_long_ui.txt` і `export --shorten` беруть лише кнопки й назви.

**Запис мови в `LocalizationTypes.xml`** береться з `localization_type_uk.xml`. Правте шаблон (колонки
`column_style_*` / `table_*` — відступи колонок у підказках з вартістю, роздільники чисел), а `build`
перенесе правки в гру.

**Заборонені слова** перелічено в `forbidden_uk.txt` (регулярний вираз, TAB, пояснення). Їх ловлять `check`, `import` і `build`.

**Русизми й кальки** — у `russisms_uk.txt`. Рядки без префікса — помилки (блокують `check`), рядки з «?» —
підозри: `check` показує їх як примітки, а `build` збирає у `build_suspects.txt` для редактора.

**Літературна редактура** (природність мови, кальки, витієватість):

```
python hotm_uk.py export --style --words 4500 --items 350   # раунд sNN по оповідному тексту й довгих назвах
python hotm_uk.py claim claude-style --ids 029,030        # або claim claude-style 12
python hotm_uk.py import
```

Батчі цього режиму мають `"partial": true`: редактор повертає лише змінені id, решта вважається без змін.
Правила природності — розділ «Природність» у `STYLE_uk.md`, чеклист синтаксичних кальок з англійської
(зайве «щоб», «перш ніж» замість «щоб не», «речі», зайві присвійні тощо) — розділ «Синтаксис» там само.
Інструкція редактора в батчі посилається на обидва.

## Розповсюдження (архів для інших гравців)

```
python hotm_uk.py dist --release 1.3
```

Команда збирає в `dist\`:
- `HotM_Ukrainian_<реліз>.zip` — `Ukrainian.xlsx`, запис мови, «Встановити.bat» / «Видалити.bat» (Windows,
  самі знаходять гру в бібліотеках Steam), `install.sh` / `uninstall.sh` (Linux / Steam Deck) і `ЧИТАЙМЕНЕ.txt`;
- `steam_guide_<реліз>.txt` — назва, опис і текст посібника для Steam (BBCode), з розділом «Історія версій»;
- `steam_changenote_<реліз>.txt` — короткий текст для поля «Примітки до змін», коли оновлюєте посібник у Steam;
- `banner_uk.png` (шапка посібника), `capsule_uk.png` (капсула з підписом «СЕРЦЕ МАШИНИ», як у корейській версії),
  `preview_uk.png` (квадратне прев'ю). Їх малює `python dist_template\make_official_art.py` з офіційних артів
  у `dist_template\art_src\`. Самі арти Arcen у репозиторій не входять: покладіть їх туди локально.

Автора, контакт, посилання на Google Drive й банер записують у `dist_template\info.json`.
Тексти шаблонів лежать у `dist_template\` (`ЧИТАЙМЕНЕ.txt`, `steam_guide.txt`). Перед кожним релізом допишіть
запис зверху `dist_template\changelog.txt` (`## версія | дата | версія гри`, далі пункти `- …`): `dist` вставляє
історію в посібник і ЧИТАЙМЕНЕ, а найновіший запис — у `steam_changenote_<реліз>.txt`, і попереджає, якщо версія
в changelog не збігається з `--release`.

## Озвучка (прототип)

`voice_mod\` — мод UkrVoice для офіційної системи модів гри (Harmony). Він озвучує український текст
голосом [StyleTTS2 · RosKud](https://huggingface.co/patriotyk/styletts2_ukrainian_multispeaker_hifigan)
(донавчена українська StyleTTS2) прямо під час гри. Поки що це прототип для локального використання: синтез
іде на льоту й потребує відеокарти NVIDIA та Python-середовища з моделлю; гравцям він не розповсюджується.

Що озвучується:
- вікна подій, розмов з NPC, ключових повідомлень, вибору цілі проєкту й статті довідника — одразу, разом
  із заголовками та підзаголовками;
- підказки до варіантів вибору, завдань і проєктів у списку справа — коли миша затрималась на них пів секунди.
  Підказка не перебиває текст вікна, що саме звучить.

Клавіші: **Ctrl** на підказці — прочитати її зараз або зупинити; **F9** — повторити текст вікна спочатку.
Мод нічого не змінює в грі й досягнень не блокує.

Встановлення (потрібні Visual Studio Build Tools; модель голосу — в теці `StyleTTS2-RosKud\` поруч, у git її немає):

```
powershell -ExecutionPolicy Bypass -File voice_mod\install.ps1 -TtsPython <python з styletts2-inference> -TtsEnv <env.ps1 або пусто>
```

Скрипт збирає DLL, кладе мод у `XMLMods\UkrVoice` і налаштовує помічника синтезу. Далі увімкніть мод у
налаштуваннях модів гри й перезапустіть її. Без Python-середовища мод для перевірки читає англійський
оригінал голосом Windows. Що мод побачив і озвучив — у `XMLMods\UkrVoice\UkrVoice_log.txt`.

**Наголоси** розставляються заздалегідь, бо бібліотека наголосів повільна й помиляється:

```
<python з ukrainian-word-stress> -X utf8 voice_mod\make_stress.py --envfile <env.ps1>
```

- `voice_mod\stress\stressed_uk.tsv` — наголошений текст (генерується; повторний запуск обробляє лише нові й змінені рядки);
- `voice_mod\stress\stress_review.txt` — слова, де бібліотека поставила кілька наголосів, — кандидати на правку;
- `voice_mod\stress\stress_fixes.txt` — ручні правки, по слову на рядок, наголос плюсом: `працівн+ики`;
- `voice_mod\stress\speech_replace.tsv` — заміни лише для голосу: `ЛКМ` → «лівою кнопкою миші», `Shift` → «Шифт».

Помічник перечитує правки й заміни на ходу, без перезапуску гри.

Голос: RosKud (StyleTTS2 · RosKud). Модель можна використовувати некомерційно із зазначенням автора голосу.

## Обережно з текстом

- Багаторядкові рядки: в Excel новий рядок у клітинці додається через **Alt+Enter**. `build` попереджає,
  якщо кількість рядків відрізняється від англійської.
- Плейсхолдери `{0}`, `{1}`, `{LClick}` і теги `<b>`, `<color=...>`, `<link=...>`, `<sprite...>` мають лишитися.
  `build` перевіряє їх і пише проблеми в `build_warnings.txt`.
- Пробіли на початку чи в кінці рядка часто потрібні для склеювання тексту. Їх теж перевіряє `build`.
- Перед `sync`/`build` закрийте `uk_translation.xlsx` в Excel. Перед кожним `sync` робоча копія зберігається в `backup\`.
