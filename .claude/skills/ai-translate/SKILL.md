# Переклад changed/new через ШІ-батчі

Рядок `changed` уже має переклад («Українська»), але зроблений зі старого англійського тексту
(«Попередній English»). Мета — оновити цей переклад під новий оригінал, а не перекласти заново:
формулювання, які вже вичитано, мають лишитися. Рядок `new` перекладаємо з нуля.

Усі команди запускай з кореня проєкту так (у PowerShell спершу `$env:PYTHONIOENCODING="utf-8"`):

```
.venv\Scripts\python.exe hotm_uk.py --game "D:\SteamLibrary\steamapps\common\HeartOfTheMachine" <команда>
```

Далі `python hotm_uk.py …` — скорочення цього виклику. Глобальний `python` не підійде: openpyxl
встановлено лише в `.venv`.
Файли (відповіді ШІ) створюй інструментом Write, а не через shell: heredoc з кирилицею й `\n` на цій
машині ламається.

## 0. Підготовка

1. Прочитай `STYLE_uk.md`: він обов’язковий для перекладу, і інструкція в батчі на нього посилається.
2. Перевір, що `uk_translation.xlsx` і `glossary.xlsx` закриті: поруч не повинно бути `~$uk_translation.xlsx`
   чи `~$glossary.xlsx`. `import` і `build` переписують ці файли, і відкритий Excel або завадить запису,
   або потім перезапише результат старою версією. Якщо файл відкритий — попроси користувача закрити Excel
   і зачекай; експорт і переклад можна робити й з відкритим, але до імпорту він має бути закритий.
3. `git status`: якщо є незакомічені зміни в xlsx чи `text/`, скажи про це користувачу, щоб коміт
   перекладу не змішався з чужими правками.
4. `python hotm_uk.py batches` — подивись, чи немає вже раунду з батчами `pending`/`claimed`. Якщо є,
   працюй з ним, а не створюй новий: `export` пропускає рядки з відкритих батчів, тож новий раунд їх
   не міститиме.

## 1. Експорт

Що експортувати, визначає запит користувача: лише змінені — `--statuses changed`; змінені й нові —
типово (`new,changed`).

```
python hotm_uk.py status
python hotm_uk.py export --statuses changed
```

Скрипт друкує назву раунду (`batches\rNN`) і кількість батчів. «Немає що експортувати» означає, що
перекладати нічого — повідом і зупинись.

## 2. Взяти батчі

```
python hotm_uk.py claim claude <кількість батчів> --round rNN
```

`claim` оновлює в батчі поле `glossary` свіжими термінами, тому бери батчі через нього, а не читай
`pending`-файли напряму. Команда друкує пари `batches\rNN\NNN.json -> batches\rNN\out\NNN.json`.

## 3. Переклад

Для кожного взятого батчу прочитай `batches\rNN\NNN.json` і запиши відповідь у
`batches\rNN\out\NNN.json` — номер файлу відповіді збігається з номером батчу.

Формат відповіді — лише JSON-об’єкт `{"1": "…", "2": "…"}` для кожного `id` батчу, без markdown і коментарів.
Переноси рядків усередині тексту — `\n`.

Як перекладати:
- Тримайся `STYLE_uk.md` і поля `instructions`. Терміни з `glossary` обов’язкові, відмінюй їх.
- `{плейсхолдери}`, `<теги>`, кількість `\n` і пробіли на краях — точно як в `en`. Зламаний плейсхолдер
  `import` відхилить, решту лише позначить у звіті, але в грі це однаково видно.
- `de` — офіційний німецький переклад: підказка щодо змісту й роду, а не джерело для калькування.
- **Елементи з `old_uk`** (це рядки `changed`): порівняй `old_en` з `en` і внеси в `old_uk` лише ті
  зміни, яких вимагає різниця. Якщо змінилися тільки друкарські помилки, пунктуація чи повтор слова в
  англійському тексті, а `old_uk` і так передає новий зміст, поверни `old_uk` без змін (але звір пробіли
  на краях і `\n` з новим `en`). Не переписуй вдалий переклад «заради стилю»: користувач його вже бачив,
  і зайві зміни лише ускладнять вичитку.

Якщо батчів кілька, можна перекладати паралельно субагентами, по одному на батч. Кожному передай
шляхи до `STYLE_uk.md`, батчу й файлу відповіді, правила вище і заборону запускати `import`, `build`
чи інші команди, що змінюють xlsx: імпорт робиш ти один, після перевірки всіх відповідей.

## 4. Перевірка до імпорту

```
python hotm_uk.py check batches\rNN\NNN.json
```

для кожного батчу. Виправ у файлі відповіді все, що вказано як проблему, і перевір ще раз, доки не буде
`OK`. Примітки «переклад ідентичний англійському» нормальні для брендів і латинських назв; інакше
перекладіть рядок.

## 5. Імпорт

Переконайся ще раз, що Excel закрито (`~$*.xlsx` немає), тоді:

```
python hotm_uk.py import
```

Імпорт ставить рядкам статус `mt`, у «Перекладач» пише `claude` і очищає «Попередній English».
Підсумок друкується по батчах (`ok`, `warn`, `rejected`, `stale`, `missing`).

## 6. Розбір після імпорту

1. Якщо імпорт надрукував `Зауваження: batches\import_….txt` — прочитай файл:
   - `ВІДХИЛЕНО: плейсхолдери` — рядок не записано, він лишився `changed`/`new`. Виправ відповідь
     і імпортуй її знову (див. нижче).
   - `англійський текст змінився після експорту` — між export і import був `sync`. Такі рядки потраплять
     у наступний `export`; повідом користувача.
   - Інші попередження (переноси, пробіли, теги, задовгі кнопки) — рядок уже записано. Переглянь кожен:
     якщо це справжня помилка, виправ.
2. `python hotm_uk.py audit --by claude` — шукає зсуви й чужий текст (коли переклад одного рядка
   опинився в іншому). Такий зсув уже траплявся в історії проєкту, і `import` його не ловить, бо
   він бачить лише формат, а не зміст. Підозрілі рядки звір з оригіналом.

Повторний імпорт виправленої відповіді: відредагуй `batches\rNN\out\NNN.json` і запусти
`python hotm_uk.py import --force batches\rNN\out\NNN.json`. `--force` потрібен, бо рядки вже мають
статус `mt`; він переімпортує весь файл, тож перед цим переконайся, що інші рядки в ньому правильні.

## 7. Збірка й коміт

```
python hotm_uk.py build
```

`build` оновлює `text/`, пише `Ukrainian.xlsx` у теку гри й друкує попередження. Нових попереджень для
щойно перекладених рядків бути не повинно; якщо є — виправ, як у кроці 6.

Закоміть разом `uk_translation.xlsx`, `text/` і `terms_ignore.json`, якщо він змінився. Тека `batches/`
ігнорується git, тож батчі й звіти імпорту лишаються лише локально. Повідомлення українською, наприклад:

```
Переклад changed після <версія> b<збірка>: <N> рядків (раунд rNN)
```

## 8. Звіт користувачу

Коротко: скільки рядків перекладено, скільки відхилено чи пропущено і чому, що знайшли `check`/`audit`,
хеш коміту. Нагадай, що імпортовані рядки мають статус `mt`: їх варто вичитати в Excel і поставити `ok`.
Для `changed`-рядків, де ти лишив `old_uk` без змін, теж скажи про це — користувачу корисно знати, що
зміна в оригіналі була косметичною.
